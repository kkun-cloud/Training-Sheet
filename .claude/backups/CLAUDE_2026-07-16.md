# TRAINING.LOG — 筋トレ記録PWAアプリ 再構築仕様書

## プロジェクト概要

筋トレ記録を管理するシングルページPWA風HTMLアプリ。GitHub Pages（`kkun-cloud.github.io`）でホスト。ビルドツール不要、単一`index.html`で動作。データ永続化はlocalStorage。

---

## 技術スタック

- **HTML/CSS/JS** — 単一ファイル、フレームワークなし
- **Chart.js 4.4+** — CDN読み込み（`https://cdn.jsdelivr.net/npm/chart.js@4.4.0/dist/chart.umd.min.js`）
- **Google Fonts** — Noto Serif JP (400,700,900) / Noto Sans JP (400,500,700) / JetBrains Mono (400,700)
- **localStorage** — データ永続化（3つのキー: `training_log_v1`, `training_log_prefs_v1`, `training_log_draft_v1`）

## 画面構成（4タブ）

### 1. TODAY — 今日の記録入力

**構成要素（上から順）：**
1. バックアップ警告バナー（3日以上未バックアップ＆自動バックアップOFF時のみ表示）
2. 週セット数進捗パネル（5部位のゲージバー）
3. 日付ピッカー（type="date"）＋曜日表示ピル
4. 曜日タブ（日〜土、7ボタン。メニュー切替用、日付は変わらない）
5. 種目カード（後述）
6. SAVE LOGボタン（フローティング、dirty時のみ表示）
7. 休憩タイマー（フローティング）

**曜日タブの挙動：**
- 通常：その日の曜日メニューが表示される
- 別曜日タップ：`overrideDay`としてメニュー切替（日付は変えない）
- オーバーライド時：「CUSTOM · ○曜に○メニューを実施」バナー＋RESETボタン
- 現在の曜日に金色●マーク表示
- 日付変更時にoverride自動リセット

**種目カード構成：**
```
┌──────────────────────────────────┐
│ 種目名 [BO][3/7]          役割   │ ← ヘッダー
├──────────────────────────────────┤
│ 前回 5/24 [5+5_BO] [UP]         │ ← 前回ログ行
│ 85kg · 5+5 × 1 / BO 80×6 @8    │
│                        [↺ COPY] │
├──────────────────────────────────┤
│ 体調: [良好] [普通] [疲労気味] [不調] │ ← 体調ピル
├──────────────────────────────────┤
│ WEIGHT     REPS¹  REPS²  SETS   │ ← 入力グリッド
│ [-2.5][入力][+2.5] [  ]  [  ]  [  ] │ ← WEIGHTにステッパー
├──────────────────────────────────┤
│ BO WT    BO REPS  BO SETS       │ ← has_bo=true時のみ
│ [  ]     [  ]     [  ]          │
├──────────────────────────────────┤
│ 3/7 WT   3/7 REP  DONE          │ ← has_37=true時のみ
│ [  ]     [  ]     [✓/✗/—]       │ ← 左肩に赤い「3/7」ラベル
├──────────────────────────────────┤
│ RPE (目標 8)                     │ ← RPEピル
│ [6] [7] [8●] [9] [10]  前回 8   │ ← 目標RPEに金色ドット
├──────────────────────────────────┤
│ MEMO [________________]         │
├──────────────────────────────────┤
│ VOL 850 / BO 480 / 3·7 1375     │ ← 自動計算
│ 1RM 102                [👑 PR]  │ ← Epley式
├──────────────────────────────────┤
│ [▶ 2:00 休憩] [▶ 3:00] [3/7×4]  │ ← タイマーボタン
└──────────────────────────────────┘
```

**特殊種目: HLR（ハンギングレッグレイズ）**
- REPSとSETSのみの簡易入力（WEIGHT不要）
- 1RMなし、VOLなし

**COPY LAST ボタン挙動：**
- 前回の全フィールド（weight/reps/sets/BO/3-7/RPE）を一括コピー
- 体調は前回と違う可能性が高いのでコピーしない
- タップ後「✓ COPIED」表示（緑、1.2秒で戻る）
- 入力が空の時に押すと前回値からステッパーで調整開始

**体調の伝播ロジック：**
- 最初の種目で体調を選ぶと、まだ触ってない他のカードにも自動反映
- 既に体調が設定済み（手動 or 保存済み）のカードは上書きしない
- SAVE後・日付変更時にリセット

**重量ステッパー：**
- WEIGHT入力の左右に `−2.5 / +2.5` ボタン
- 入力が空なら前回値をベースに加減算
- タップで微小バイブ（`navigator.vibrate(20)`）
- inputグリッドは `2fr 1fr 1fr 1fr` で WEIGHT セルを広めに取る

**自動下書き保存：**
- markDirty() のたびに localStorage (`training_log_draft_v1`) に全カード状態を保存
- リロード・タブ切替から戻った時に自動復元
- SAVE完了時にドラフトクリア
- 日付変更時にドラフトクリア

**離脱警告：**
- 未保存データがある状態でのタブ切替 → confirmダイアログ
- ブラウザリロード・閉じる → beforeunloadイベント

**保存後のスクロール位置維持：**
- SAVE後にrenderTodayで再描画するが、scrollYを保存→復元

### 2. HISTORY — 種目別履歴

**構成要素：**
1. 種目セレクタ（プログラムから消した種目も「（旧）」付きで表示）
2. プロトコルフィルター（ピル列、横スクロール。1種類しかなければ非表示）
3. メトリック切替トグル：WEIGHT / 1RM / VOL / REPS
4. 統計グリッド（MAX WEIGHT / EST 1RM / PRs · N回）
5. チャート（Chart.js line、PRポイントを金色マーカーで表示）
6. LOG ENTRIES リスト（日付＋プロトコルタグ＋値＋インジケーター＋メモ表示）

**プロトコルフィルター：**
- `ALL 27` / `25rep 15` / `5+5_BO 4` のようにプロトコル名＋件数
- フィルター選択で統計・チャート・ログ全てが絞り込まれる
- 種目変更時にフィルターは `all` にリセット

---

### 3. STATS — ダッシュボード

**構成要素：**
1. OVERVIEW（総セッション数、期間、PR数、種目数、連続週ストリーク）
2. PROGRESSION（種目選択式のチャート。実重量＋推定1RMの2系列重ね描き）
3. RECENT PRs（直近8件のPR一覧、タップでHISTORYジャンプ）
4. STAGNATION ALERT（停滞検出ビュー）
5. WEEKLY VOLUME（過去8週の部位別ボリューム積み上げ棒グラフ）

**停滞検出：**
- 全種目を停滞スコア（0-100）で降順ソート
- スコア計算: 最終PRからの経過回数×8(max40) + 21日超過分(max30) + FLAT/WARN率×30
- レベル: 重度(60+)/中度(35-59)/軽度(15-34)/順調(14以下)
- 直近5回のインジケーター推移をドットで可視化
- アクション提案を併記（progression ruleベース）
- ALL / 警告のみ トグル
- カードタップ → HISTORY画面へジャンプ

---

### 4. SETTINGS — 設定

**セクション構成：**
1. DATA（エクスポート/インポート/初期データ再投入/全削除）
2. BACKUP（自動バックアップトグル＋最終バックアップ情報＋警告テキスト）
3. PROGRAM（週セット数目標編集/種目・曜日メニュー編集/デフォルトに戻す）
4. PROTOCOL（3/7法の説明、Progression Rules）
5. INDICATORS（インジケーター凡例）

**プログラム編集モーダル：**
- 7曜日タブで切替
- セッション名・部位のテキスト編集
- 種目リスト（並び替え↑↓、編集、削除）
- 「+ 種目を追加」ボタン

**種目編集モーダル：**
- 名前 / ID（新規時のみ編集可、英数字_のみ）/ 役割 / 目標RPE / スペック表記
- 部位チップ（複数選択: 胸/背中/肩/肩(サイド)/肩(リア)/脚/二頭/三頭/コア）
- プロトコル拡張チェック（BO / 3/7法）
- ID重複バリデーション

**破壊的操作の保護：**
- 「初期データ再投入」→ 実行前に自動バックアップダウンロード
- 「全データ削除」→ 自動バックアップ → 2段階確認

## 計算ロジック

### Volume計算
```
split-set (reps2あり): weight × (reps1 + reps2)
通常: weight × reps1 × sets
BO: bo_w × bo_r × bo_s
3/7: f37_w × f37_r
```

### 推定1RM（Epley式）
```
1RM = weight × (1 + min(reps1, 12) / 30)
// 12rep上限で打ち切り
// main と BO の高い方を採用
// 3/7は除外
```

### プロトコル推測（inferProtocol）
```
reps2あり → "5+5" + (BO ? "_BO" : "") + (37 ? "_37" : "")
reps1 >= 20 → "25rep"
それ以外 → "8x3" + (BO ? "_BO" : "") + (37 ? "_37" : "")
```

### インジケーター判定（プロトコル対応）
同プロトコルの過去ログと比較（1件以上あれば。なければ全期間フォールバック）

| 優先度 | 条件 | ラベル | CSS |
|--------|------|--------|-----|
| 1 | 過去最大重量超え | 重量PR | `ind-pr-w` 👑 PR |
| 2 | 同重量で過去最多rep | rep PR | `ind-pr-r` 🔥 rep |
| 3 | 総Vol過去最大 | vol PR | `ind-pr` ✨ vol |
| 4 | 直近3回平均より重量5%↓ or vol 15%↓ | 要注意 | `ind-warn` WARN |
| 5 | 前回と重量・vol完全一致 | 停滞 | `ind-flat` FLAT |
| 6 | 上記どれにも当たらない | 順調 | `ind-up` UP |
| 7 | 過去データなし | 初回 | `ind-init` NEW |

### 週セット数カウント
```
split-set (reps2あり): 2セット
通常: sets値
BO: bo_s値（デフォルト1）
3/7: 1セット
```

## 休憩タイマー

### 仕様
- **終了時刻ベース** (`endTime = Date.now() + seconds * 1000`)。setIntervalが止まっても正確
- `visibilitychange` イベントで復帰時に残時間を再計算
- 残り10秒以下: 赤パルスアニメーション + ビープ音（880Hz）
- 0秒: バイブ（200-100-200-100-400ms） + 完了音（660Hz→880Hz）+ toast
- 4秒後に自動非表示
- `−15 / +15` ボタンで途中調整
- `×` ボタンで強制停止

### タイマーボタン（各種目カード）
- `▶ 2:00 休憩` — 標準（120秒）
- `▶ 3:00` — 高強度用（180秒）
- `3/7 ×4 (15s)` — 3/7法対応種目のみ表示（15秒）

### ビープ音（WebAudio）
```js
function beep(freq, dur) { /* sine波、exponentialRamp */ }
```

## バックアップシステム

### 警告バナー
- 3日以上バックアップなし＆自動バックアップOFF時にTODAY上部に黄色バナー表示


### インポート

## 既知の設計判断

1. **ジムの重量差**: 器具の重量表示が実際と異なるジムの場合、÷2した重量で記録。memoにジム名を記載
2. **プロトコル分離**: 25rep時代と5+5_BO時代は別プロトコルとして判定。同プロトコルの過去ログのみと比較
3. **間接刺激は週セット数に含めない**: 直接刺激のセット数のみ管理
4. **削除した種目の記録保持**: メニューから種目を消しても過去レコードは残る。HISTORYで「（旧）」として閲覧可能
5. **split-set（reps2あり）は2セットカウント**: 5+5は1セットではなく2セット分の刺激
